# Glossary

| Term | Meaning in this playbook |
|---|---|
| **Lead** | The person who commissions the work, sets the intent, judges and approves; their visual judgement wins |
| **Agent** | The AI coding agent (Claude Code in practice): researches, builds, measures, checks, documents; decides alone what is reversible |
| **Check** | A verification run by the agent, with its result quoted |
| **Approval** | An explicit decision by the lead after seeing the result |
| **Final conditions** | Display size, normal speed, final processing, target platform, whole piece, latest version |
| **Key criterion** | The sentence of the brief against which every iteration is judged |
| **Sample** | A representative element, excerpt or frame on which a method is tuned before it is generalized |
| **Validation excerpt** | A continuous portion of the final production, made with the delivery settings |
| **Diagnosis by elimination** | Neutralizing one possible cause at a time until the defect disappears |
| **Feature inventory** | The list of features a result must show, each with a measurement, a threshold and a review view, written before generation; a feature judged "sketchy" blocks delivery |
| **Counter-trial** | An extreme variant ("treat everything", "almost nothing") shown to reveal a preference |
| **Named modification** | A trial change applied by a test bench to a copy of the reference state, under a name (`e1`, `e2`) |
| **Fingerprint** | SHA-256 of every dependency of a production; protects a resume against mixing versions |
| **Stale outputs** | Outputs of an outdated state, moved (never deleted) to `_stale/` |
| **Loop seam** | The passage from the last frame to the first; invisible when it is of the same order as a consecutive difference |
| **Flicker** | A pixel that lights up then goes dark from one frame to the next (strong temporal acceleration, back and forth) |
| **Temporal stabilization** | Correcting only temporal spikes with a median of three motion-compensated frames, without spatial blur |
| **Cost profile** | Measuring where time goes and comparing setting profiles on the same units |
| **Instruction register** | The list of durable, active and replaced instructions, and of requests with their status |
| **Log** | A numbered trace of the trials and decisions of a version or workstream; a trace, not a source of rules |
| **Workstream** | A long task (several steps or sessions) with its own branch and log |
| **Leftovers** | Elements that must not survive into a deliverable: signature, logo, placeholder text, watermark, debug setting |
| **D / T / H / O** | Status of a research claim: documented, tested, hypothesis, observation |
| **[proven] / [extrapolated] / [proposed]** | Maturity levels of a practice in this playbook |
| **Apple gamma pre-compensation** | A gamma correction of a video stream intended for Apple's video stack |
| **2.5D** | Animating an image through layers projected onto light geometry, without a full 3D reconstruction |
