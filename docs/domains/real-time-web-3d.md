# Real-time 3D for the web

Practices **[proven]** on real-time WebGL productions (three.js rendering, assets generated by code and baked in
Blender, glTF delivery), on two subjects of opposite nature: one reproducing a reference, one original creation.
Transferable to other real-time engines unless stated otherwise. Games beyond the web remain [extrapolated].

## Principles specific to real time

1. **References before criteria, criteria before trials.** A board of real references (photos, video, reference asset
   kept private), then a written **feature inventory** with a measurement, a threshold, a reference and a review view
   for each feature, committed before the first generation. An original creation needs real references too: literature
   gives numbers, not shapes.
2. **One piece or layer per observed part**, with the construction method suited to its shape (see below). A single
   painted surface is not a construction.
3. **The detail budget comes from the closest framing of the application**: at least one texel per screen pixel, and a
   maximum mesh edge length in the detailed regions, both measured on the delivered asset.
4. **Measure without rendering to iterate, render to prove.** Measurement series without rendering drive the tuning;
   the proof is a capture of the delivered asset in the test bench, with the same renderer as the reference.
5. **The tuning objective contains what the eye judges.** A term missing from the objective lets that aspect drift
   (silhouettes out of phase while the skeleton matches, a whip instead of a wave along an appendage).
6. **Reproducible to the byte**: declarative configuration, explicit seeds, one random stream per part and per use;
   the same configuration produces the same binary asset.

## Toolkit shared between projects

- A **single source** repository for the shared toolkit; each project keeps a **versioned copy** described by a
  manifest (source commit, checksum of every file).
- A check in each project reports any local edit of the copy; a fix is made in the toolkit, then copied again. A
  weakness revealed by one project is fixed in the toolkit and rechecked on every project.
- Generic methods in the toolkit, values specific to a subject in its configuration
  ([P11](../principles.md#p11)). `scripts/new_project.py` applies the same idea to the playbook's tools.

## Phases and exit gates

| Phase | Exit gate |
|---|---|
| References and study (parts, junctions, materials, motions measured on the references) | Board and sources recorded, licences noted |
| Brief and feature inventory (with detail budget) | Inventory committed before the generator |
| Construction, rig, primary motion | Tests; connectivity at rest; exact loop seam |
| Secondary motion (simulated chains, waves along appendages) | Wave signature and coordination measured |
| UV atlas and textures, baking | Texels per pixel; no UV outside [0, 1]; no overlap inside or between parts |
| Export (glTF) | Khronos validator without errors |
| Bench and review | Close-ups per feature, side by side with the reference; a written note per feature |
| Checks and delivery gate | Every measurement passes, every note exists, no feature judged "sketchy" or "absent" |

## Construction by shape

| Shape | Method |
|---|---|
| Hanging appendages (tentacles, arms, strands, barbels) | Simulated chains; a bending wave locked to the primary motion (tangent angle, amplitude and phase along the chain), root following the body, lateral orbits in quadrature, rigid tip, inertia and drag |
| Fins and membranes | One ray = one guide chain; membrane between rays with folds; irregular free edge; wave along the rays with a phase shift from ray to ray |
| Openings (mouths, cavities) | A folded loft whose lip varies with the angle; cavity and lips in a reserved band of the atlas |
| Scaled or plated skin | Overlapping scales (the anterior one covers), shadow under each free edge, per-scale variation, colour sampled at each scale's centre |
| Gelatinous or glass bodies | Layers of transmission, pigment, inner parts visible in section |
| Soft skinning | B-spline weights over four joints for soft chains |

## Checks

| Check | What it measures |
|---|---|
| Coordination | Cumulative delays, amplitudes, driven share, harmonics between parts (when a reference exists) |
| Wave | Delay of the wave along each chain, relative amplitude, curvature, wavelength, non-rigid share |
| Swing | Range of motion of each appendage in the frame of its joint; crossing of the median plane |
| Transitions, repetition, regularity | Seams between cycles, identical instances, mechanical regularity |
| Connectivity | Gaps opening between parts during motion |
| Feature inventory | Local relief, cavities, counts of repeated elements, texture density, mesh resolution, atlas integrity |
| glTF validity | Khronos validator |
| Performance | Frame cost and frame rate in motion |

- **Every moving part has a motion measurement and a review view in motion**: an appendage that nobody measures can
  flail without any check seeing it.
- **The atlas is checked like geometry**: UVs read outside [0, 1] repeat the other end of the atlas; overlapping texels
  mix two regions; both are measured on the delivered asset.
- **A bench frame that depends on mesh density moves when a region is refined**: use area-weighted means and
  quantiles.
- **A measuring instrument is validated on constructions whose answer is known** before it is trusted
  ([P1](../principles.md#p1)).

## What failed, and the rule kept

| Failure | Rule |
|---|---|
| Every check passed on a rudimentary result | A feature inventory with blocking review notes ([A21](../quality/anti-patterns.md#a21)) |
| A measurement was written in a report for weeks without a threshold | A measurement enters a gate, or it does not count ([A22](../quality/anti-patterns.md#a22)) |
| A review note described what the generator should have produced, not what the capture showed | Reread the final capture before confirming a note; review the notes after any rebuild ([iteration, rule 8](../workflow/04-evidence-based-iteration.md)) |
| A literature envelope in the wrong unit | Explicit units in the configuration |
| Sequence tables not periodic at the seam; identical cycle instances | Tables computed over the period; slow modulations between instances |
| A recursive delete crossed directory junctions on Windows | Remove junctions before deleting a tree |
